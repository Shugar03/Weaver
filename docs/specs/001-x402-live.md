# Spec 001 — x402 live E2E: pay → settle → serve en Monad

## Estado actual

`EvmFacilitatorVerifier` (`packages/settlement/src/verifier.ts`) implementa
`verify`+`settle` contra `x402-facilitator.molandak.org` con el wire v2
canónico. Probado con **mocks**; live solo llegó a `/verify` → ECRecover en
simulación. Jamás se ejecutó un `/settle` real que mueva USDC.

## Goal

Un cliente real paga 0.01 USDC vía EIP-3009 `transferWithAuthorization`,
el facilitator lo settlea on-chain, y el gateway sirve el job. Evidencia:
`transaction` hash real del settle + Transfer del USDC al `payTo` on-chain.

## Diseño

`scripts/e2e-x402.mjs` (patrón de `e2e-live.mjs`):

1. Gateway de prueba con `PAYWALL_PAY_TO=<operator addr>` +
   `X402_FACILITATOR` (default molandak) + forge real conectado.
2. Client EOA nuevo → fondeo USDC desde operator wallet (`transfer` 0.05).
3. Cliente firma EIP-712 `TransferWithAuthorization`
   (domain `{name:"USDC",version:"2",chainId:10143,verifyingContract:USDC}`)
   con viem `signTypedData` — nonce random bytes32, ventana validAfter/
   validBefore.
4. `X-PAYMENT` = base64(`{x402Version:2, scheme:"exact", network:"eip155:10143",
   payload:{signature, authorization}}`) → POST `/v1/chat/completions`.
5. Assert: 200 + SSE `data:` + job done. Luego receipt on-chain del tx que
   devuelve el facilitator (el middleware expone `X-PAYMENT-RESPONSE` o se
   lee de telemetría/logs — lo que ya exista; si no, scan del último
   Transfer hacia payTo).

## Fail-closed ya cubierto (no re-testear live)

payload forjado / payTo ajeno / amount menor → 402 (tests unitarios verdes).

## Non-goals

- Paywall en el deploy público — queda opt-in por env.
